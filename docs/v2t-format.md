# .v2t text format (version 3) and the font

A `.v2t` file holds text that the build has already word-wrapped, ready to draw into a
hires bitmap with a proportional font. The C64 only draws glyphs and colours cells; it
doesn't wrap. `vic2/build.py` makes one from `input/<name>.txt` for the free area beside
the image. `asm/v2t.inc` draws it ([v2t-lib.md](v2t-lib.md)).

On disk it is a PRG file with load address `$1800`, named like its image (cut to 12
characters) plus `.txt`. Like `.v2i`, it can be loaded anywhere.

## Layout

| offset | size | field |
|---|---|---|
| 0 | 3 | magic `"V2T"` |
| 3 | 1 | format version, 3 |
| 4 | 1 | character column of the text area |
| 5 | 1 | character row of the text area (top of the first line) |
| 6 | 1 | width of the area in cells |
| 7 | 1 | number of lines that follow |
| 8 | 1 | font: 0 = the built-in font below (other values are reserved) |
| 9 | 1 | leading: blank pixel lines between text lines |
| 10 | ... | lines |

Each line is a colour byte (`fg << 4 | bg`), a glyph count n, then n screen codes.

## Drawing rules

- **Spacing:** line i starts `8 + leading` pixel lines below line i - 1. With leading
  other than 0, lines aren't aligned to character rows, and a line can touch two rows.
- **Colour:** a non-empty line colours the cells of every character row it touches, from
  the area's column across its width. Where two lines share a row, the later line's colour
  wins. An empty line (n = 0) colours and draws nothing; it is just vertical space.
- **Glyphs:** a glyph is OR'd into the bitmap at its pixel x, then x moves on by the
  glyph's advance.
- **Wrapping:** the builder wraps a line only if its width minus the last glyph's spacing
  column fits the area. The spacing column may hang one pixel past the edge.
- **Clipping:** a glyph that would end further right is not drawn, and neither is any
  glyph after it. Glyph rows below character row 24 are not drawn.
- **Text file input:** paragraphs are separated by blank lines. A paragraph starting with
  `# ` is a title, white (`$10`). Body text is light grey on black (`$f0`). Paragraphs
  are separated by an empty line.

## The font

`font.inc` is generated by `vic2/font.py` from the C64 character ROM (the lower/upper
case set), which the build reads from VICE's installation. It defines two tables, indexed
by screen code 0-127 (reverse video codes 128-255 use the same glyph as code & 127):

- `v2t_font_w` (128 bytes): the advance of each glyph in pixels. That is its width plus
  one spacing column, or 4 for blank glyphs such as space.
- `v2t_font_g` (128 x 8 bytes): the glyph's 8 rows, top first. The most significant bit is
  the leftmost pixel. Glyphs are trimmed to their non-blank columns and stored left
  aligned, so the glyph's ink spans bits 7 down to `8 - (advance - 1)`.

Characters map to screen codes as in the lower/upper case set: `a-z` are 1-26, `A-Z` are
65-90, digits and most punctuation keep their ASCII value, and `@` is 0. `screen_code` in
`vic2/font.py` does the conversion. Letters average about 6.8 pixels, so a 40-column
screen holds about 47 characters per line.

Another font in the same format can be swapped in by replacing `font.inc`. The header's
font byte is reserved for selecting fonts later.
