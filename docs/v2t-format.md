# .v2t text format (version 4) and the font

A `.v2t` file holds text that the build has already word-wrapped, ready to draw into a
hires bitmap with a proportional font. The C64 only draws glyphs and colours cells; it
doesn't wrap. `vic2/build.py` makes one from `input/<name>.txt` for the free area beside
the image. `asm/v2t.inc` draws it ([v2t-lib.md](v2t-lib.md)).

On disk it is a PRG file with load address `$1800`, named like its image (cut to 12
characters) plus `.txt`. Like `.v2i`, it can be loaded anywhere.

## Layout

| offset | size | field |
|---|---|---|
| 0 | 3 | magic `"V2T"` |
| 3 | 1 | format version, 4 |
| 4 | 1 | character column of the text area |
| 5 | 1 | character row of the text area (top of the first line) |
| 6 | 1 | width of the area in cells |
| 7 | 1 | number of lines that follow |
| 8 | 1 | height of the font the text was laid out for, H (`v2t_draw` refuses others) |
| 9 | 1 | leading: blank pixel lines between text lines |
| 10 | ... | lines |

Each line is a colour byte (`fg << 4 | bg`), a glyph count n, then n character codes:
ASCII 32-127, as GEOS fonts have them. Codes 128-255 are drawn as code & 127, codes below
32 as a space.

## Drawing rules

- **Spacing:** line i starts `H + leading` pixel lines below line i - 1. Unless H +
  leading is a multiple of 8, lines aren't aligned to character rows, and a line touches
  every row its H pixel lines reach (two for the 8 pixel ROM font, up to five for a 26
  pixel one).
- **Colour:** a non-empty line colours the cells of every character row it touches, from
  the area's column across its width. Where two lines share a row, the later line's colour
  wins. An empty line (n = 0) colours and draws nothing; it is just vertical space.
- **Glyphs:** a glyph is OR'd into the bitmap at its pixel x, then x moves on by the
  glyph's width (which includes its spacing).
- **Wrapping:** the builder wraps a line only if its width minus the font's *hang* fits
  the area. The hang is the fewest blank columns any glyph with ink has at its right
  (1 for the ROM font): the last glyph may stick out that far past the edge.
- **Clipping:** a glyph that would end further right is not drawn, and neither is any
  glyph after it. Glyph rows below character row 24 are not drawn.
- **Text file input:** paragraphs are separated by blank lines. A paragraph starting with
  `# ` is a title, white (`$10`). Body text is light grey on black (`$f0`). Paragraphs
  are separated by an empty line.

## The font

`font.inc` is generated by `vic2/font.py` from one point size of a font (a GEOS font
record, or the character ROM, see below). It is laid out for drawing speed: each glyph is
cut into byte columns, 8 pixels wide, stored one after the other, each H bytes from the
top row down (most significant bit leftmost, the bits right of the glyph's width 0). Only
the columns up to the last one with ink are stored; glyphs with the same columns share
them.

| label | size | |
|---|---|---|
| `v2t_font_w` | 96 | width in pixels of the glyph for each code 32-127, its spacing included (the x advance, at most 240) |
| `v2t_font_nb` | 96 | its byte columns (0 for a blank glyph such as space) |
| `v2t_font_lo`, `v2t_font_hi` | 96 each | address of its first column |
| `v2t_font_data` | | the columns |

and the constants `V2T_FONT_H` (H) and `V2T_FONT_HANG`. A glyph's byte is drawn as two
bitmap bytes, shifted right by x & 7, so drawing never has to gather a glyph's bits from a
bitstream. The font is assembled into the program, so everything a program draws uses
the font it was built with.

The default font comes from the C64 character ROM (the lower/upper case set), which the
build reads from VICE's installation. Each glyph is trimmed to its non-blank columns and
gets one spacing column; blank glyphs such as space are 4 wide. ASCII maps to the ROM's
glyphs as in that set (`screen_code` in `vic2/font.py`); characters without one, like `^`
or `{`, draw as spaces. It is 8 pixels high, and letters average about 6.8 pixels, so a
40-column screen holds about 47 characters per line.

`build --font FILE.cvt[:SIZE]` uses a GEOS font instead: a VLIR font file in Convert
(`.cvt`) format, its smallest point size unless SIZE picks another. `vic2/font.py` reads
the file's info block (point sizes at `$82`) and record table (blocks and bytes in the
last block per record; each record is stored in whole 254-byte blocks, only the file's
last one ends early). Mega fonts (several records per size) aren't supported. Bigger
fonts cost memory: the ROM font is 1.1K in `font.inc`, NLQ at 10, 18 and 24 points 1.4K,
2.9K and 4.7K (about 15-30% more than their packed GEOS records). The repository ships no GEOS fonts; `fonts/` is gitignored for your own.

The build writes text with `code` in `vic2/font.py`: printable ASCII as is, typographic
quotes and dashes as their ASCII forms, anything else as a space.
